# Ручные тест-кейсы — расчёт стоимости корзины

Задача: cart-pricing-f9ae3c. Фронтенда и UI-фреймворка в репозитории нет, поэтому UI-проверки ручные; автотест-билдер переносит их в раздел «manual» своей сводки.

### TC-MAN-001: Попытка установить количество 21 в строке не меняет количество
- **Traces:** REQ-3
- **Technique:** Boundary value analysis — `quantity`: max+1 (21) в UI
- **Level:** Manual — UI корзины отсутствует в репозитории, автоматизировать не на чем; текст ошибки не проверяется (Q7)
- **Priority:** P2
- **Preconditions:** Корзина содержит одну строку «MUG-01», цена 450.00, количество 20
- **Test data:** количество 20, попытка установить 21
- **Steps:**
  1. Открыть страницу корзины → Expected: в строке «MUG-01» количество 20
  2. Попытаться увеличить количество до 21 (кнопка «+» или ввод) → Expected: в поле количества остаётся 20
  3. Обновить страницу → Expected: количество в строке по-прежнему 20
- **Expected result:** После попытки и после перезагрузки количество в строке равно 20; факт показа ошибки не оценивается (REQ-2 заблокирован Q7)

### TC-MAN-002: Строка «До бесплатной доставки осталось N ₽» показывает 1000.00 при сумме 4000.00
- **Traces:** REQ-19, A6
- **Technique:** Equivalence partitioning — класс «сумма < 5000»
- **Level:** Manual — UI отсутствует в репозитории; формат N не определён (Q9)
- **Priority:** P2
- **Preconditions:** Пользователь не участник; корзина: «MUG-01», цена 1000.00, количество 4 (сумма 4000.00)
- **Test data:** сумма корзины 4000.00, порог 5000.00
- **Steps:**
  1. Открыть страницу корзины → Expected: рядом с итогом показана строка «До бесплатной доставки осталось 1000.00 ₽» (допущение A6: N = 5000 − сумма до скидки)
  2. Увеличить количество до 5 (сумма 5000.00) → Expected: строка «До бесплатной доставки осталось …» исчезает
- **Expected result:** При 4000.00 строка показывает N = 1000.00 ₽; при 5000.00 строки на странице нет. Форматирование N (знаки, разделитель) не оценивается до Q9

### TC-MAN-003: Суммы на странице корзины равны значениям ответа API
- **Traces:** REQ-17
- **Technique:** Equivalence partitioning — класс «участник, 3000 ≤ сумма < 5000» (проверка проводки, а не правила)
- **Level:** Manual — UI отсутствует в репозитории; это проверка, что фронтенд не пересчитывает суммы сам
- **Priority:** P1
- **Preconditions:** Пользователь — участник лояльности; нет распродажи; корзина: «MUG-01», цена 700.00, количество 5; открыты инструменты разработчика (вкладка Network)
- **Test data:** ожидаемые значения: subtotal 3500.00, discount 175.00, shipping 300.00, total 3625.00
- **Steps:**
  1. Открыть страницу корзины и найти в Network ответ `POST /api/cart/price` → Expected: ответ содержит `subtotal`, `discount`, `shipping`, `total`
  2. Сравнить суммы на странице с полями ответа → Expected: каждая отображаемая сумма (3500.00, 175.00, 300.00, 3625.00) совпадает с соответствующим полем ответа
- **Expected result:** Все четыре суммы на странице совпадают с ответом API до копейки
