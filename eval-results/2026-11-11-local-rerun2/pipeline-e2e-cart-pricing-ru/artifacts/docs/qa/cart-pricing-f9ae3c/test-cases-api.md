# Тест-кейсы: API — `POST /api/cart/price`

Задача: cart-pricing-f9ae3c · План: `test-plan.md`.
ВНИМАНИЕ: в репозитории нет API-слоя (только `src/shop/pricing.py`). Кейсы написаны по ТЗ и годятся для прогона на стенде с API; в этом репозитории они не автоматизируются (A13 (Этап 2)). Суммы в ответе сравниваются как десятичные числа независимо от типа «число/строка» (A12 (Этап 2), Q9).

### TC-API-001: Участник, строка на 3000.00 — скидка 150.00, доставка 300.00, итог 3150.00
- **Трассировка:** REQ-14, REQ-15, REQ-16, REQ-11, A11
- **Техника:** Таблица решений — правило R1 (участник = да, распродажа = нет, сумма ≥ 3000) через контракт API
- **Уровень:** API — контракт запроса и ответа и сборка итога из `subtotal`, `discount`, `shipping` проверяются без UI
- **Приоритет:** P0
- **Предусловия:** API доступен на стенде; аутентификация, если она требуется, настроена оператором (Q5)
- **Тестовые данные:** `{"lines":[{"sku":"MUG-01","price":3000.00,"quantity":1}],"is_member":true,"is_sale_period":false}`
- **Шаги:**
  1. Отправить `POST /api/cart/price` с телом из тестовых данных → Ожидается: HTTP `200`
- **Ожидаемый результат:** `200`; тело содержит ровно поля `subtotal = 3000.00`, `discount = 150.00`, `shipping = 300.00`, `total = 3150.00`

### TC-API-004: Участник, сумма 5200.00 — доставка определяется по сумме до скидки
- **Трассировка:** REQ-10, REQ-14, REQ-11, A3, A11
- **Техника:** Таблица решений — правило «участник, сумма ≥ 5000» плюс проверка порядка расчёта: после скидки сумма (4940.00) ниже порога, но доставка не должна появляться

- **Предусловия:** API доступен на стенде
- **Тестовые данные:** `{"lines":[{"sku":"MUG-01","price":5200.00,"quantity":1}],"is_member":true,"is_sale_period":false}`
- **Шаги:**
  1. Отправить `POST /api/cart/price` с телом из тестовых данных → Ожидается: HTTP `200`
- **Ожидаемый результат:** `200`; `subtotal = 5200.00`, `discount = 260.00`, `shipping = 0.00`, `total = 4940.00`
