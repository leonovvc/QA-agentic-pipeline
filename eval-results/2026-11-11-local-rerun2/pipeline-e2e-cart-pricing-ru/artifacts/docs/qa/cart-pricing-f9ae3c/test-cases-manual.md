### TC-MAN-001: Исследование реакции `POST /api/cart/price` на некорректные и подделанные данные
- **Трассировка:** REQ-18, Q1, Q5
- **Техника:** Исследовательский чартер — у ТЗ нет проверяемого оракула для ошибок (Q1) и политики доверия к клиентским данным (Q5)
- **Уровень:** Manual — стабильного оракула пока нет; цель — собрать фактическое поведение для ответа на Q1 и Q5
- **Приоритет:** P1
- **Предусловия:** Доступен стенд с API; есть инструмент отправки HTTP-запросов (curl, Postman)
- **Тестовые данные:** варианты тела запроса: отсутствует `lines`; `lines = []`; `quantity` = 0, -1, 21, 2.5, "abc"; `price` = -1, 0, 0.001, 1e12, "abc"; дублирующиеся `sku`; `is_member` = "yes"; лишнее поле; цена, заниженная относительно каталога; `is_member = true` без аутентификации
- **Шаги:**
  1. Отправить каждый вариант из тестовых данных, записывая HTTP-код, тело ответа, время ответа → Ожидается: каждый ответ записан в протокол сессии
  2. Сопоставить записанные ответы с требованием «ошибка с понятным сообщением» → Ожидается: составлен список расхождений и вопросов для владельца ТЗ
- **Ожидаемый результат:** тайм-бокс 60 минут; протокол содержит для каждого варианта HTTP-код, тело ошибки и время ответа; отдельно отмечены случаи, где сервер принял подделанные цену или флаги, где ответ раскрывает внутренние детали (стек, пути), и новые вопросы к Q1, Q5, Q7; формализуемые кейсы переданы на следующий круг планирования

### TC-MAN-002: Исследование ошибки при вводе недопустимого количества в корзине
- **Трассировка:** REQ-4, Q6
- **Техника:** Исследовательский чартер — текст и место ошибки не заданы (Q6)
- **Уровень:** Manual — стабильного оракула пока нет
- **Приоритет:** P2
- **Предусловия:** Доступен стенд с UI корзины; в корзине есть строка с количеством 5
- **Тестовые данные:** значения количества: 0, -1, 21, 100, 2.5, пустое поле, "abc", вставка "１０" (полноширинные цифры)
- **Шаги:**
  1. Ввести каждое значение из тестовых данных в поле количества и подтвердить → Ожидается: для каждого значения записаны: показана ли ошибка, её текст и место, итоговое значение в поле
  2. Проверить, что итог корзины после каждой попытки не изменился → Ожидается: итог записан до и после
- **Ожидаемый результат:** тайм-бокс 30 минут; протокол содержит таблицу «значение → ошибка (текст, место) → количество после попытки → итог до/после»; найденные расхождения с REQ-5 оформлены как дефекты, тексты ошибок переданы владельцу ТЗ в Q6
