# ТЗ: Расчёт стоимости корзины интернет-магазина — annotated

Версия 1.2 · Владелец: продуктовая команда «Корзина и оформление»

## Контекст

Покупатель видит в корзине итоговую сумму к оплате до перехода к оформлению заказа.
Расчёт выполняется модулем ценообразования `shop.pricing` на сервере; фронтенд получает
готовые суммы через API и ничего не пересчитывает сам. [Q3: ПРОТИВОРЕЧИЕ — «фронтенд
ничего не пересчитывает», но §7 требует показать «осталось N ₽», а API (§6) такого поля
не возвращает] Все суммы — в рублях с копейками. [Q9: TRACK B — формат сумм в ответе
(число/строка, всегда 2 знака) и режим округления не заданы]

## Требования

1. **Количество.** Количество одного товара в строке корзины — от 1 до 20 включительно.
   Если покупатель пытается установить значение вне диапазона, показывается ошибка,
   а количество в строке не меняется. [Q6: TRACK B — текст/место ошибки; что делает API
   при quantity вне 1..20, 0, отрицательном, нецелом] [A7: допущение — quantity целое]

2. **Сумма корзины.** Сумма корзины — это сумма «цена × количество» по всем строкам.
   [Q7: TRACK B — допустимые значения price (0, отрицательная, больше 2 знаков), дубли
   sku, максимум строк не заданы] [A3: допущение — «сумма корзины» это сумма до скидки;
   все пороги считаются от неё]
   Пустая корзина имеет сумму 0 ₽, оформление заказа для неё недоступно. [Q2: ПРОТИВОРЕЧИЕ
   — по §3 и §5 пустая корзина получит доставку 300 ₽ и итог 300 ₽; см. A2] [Q2: механизм
   «недоступно» (кнопка неактивна / ошибка API) не задан]

3. **Доставка.** Доставка стоит 300 ₽. При сумме корзины от 5000 ₽ доставка бесплатная.
   [A4: допущение — порог включительный (≥ 5000), «от»]

4. **Скидка участника.** Участники программы лояльности получают скидку 5% от суммы
   корзины, если сумма не меньше 3000 ₽. В период распродажи скидка участника
   не действует. [A6: допущение — распродажа имеет приоритет над членством; скидка 0]
   [Q5: TRACK B — is_member и is_sale_period приходят от клиента; кто их определяет и
   проверяется ли это на сервере?] Скидка округляется до копеек. [A5: допущение — режим
   округления half-up; в ТЗ не указан]

5. **Итог.** Итог к оплате = сумма корзины − скидка участника + доставка.
   [A3: доставка определяется по сумме до скидки]

6. **API.** `POST /api/cart/price` принимает строки корзины (`sku`, `price`, `quantity`)
   и флаги `is_member`, `is_sale_period`; возвращает `subtotal`, `discount`, `shipping`,
   `total`. [Q5: TRACK B — аутентификация/авторизация, источник истины для price (клиент
   присылает цену сам), rate limiting не описаны] Ответ должен приходить быстро.
   [Q4: TRACK B — нет измеримого критерия (p95, лимит размера корзины)] Некорректный
   запрос возвращает ошибку с понятным сообщением. [Q1: BLOCKING — не заданы HTTP-коды,
   формат тела ошибки, перечень «некорректных» запросов и тексты сообщений]

7. **Отображение.** На странице корзины рядом с итогом показывается строка
   «До бесплатной доставки осталось N ₽», пока порог не достигнут. [Q3: N не определено
   (5000 − сумма корзины?), откуда берётся, формат/округление; поведение для пустой
   корзины; см. также Q8: строка при достигнутом пороге скрывается или нет] [Q8: TRACK B
   — состояние UI при пороге ровно 5000 и при пустой корзине]
