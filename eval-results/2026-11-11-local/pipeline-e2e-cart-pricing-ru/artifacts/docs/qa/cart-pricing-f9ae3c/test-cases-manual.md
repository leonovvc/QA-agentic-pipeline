# Тест-кейсы: ручные / исследовательские — cart-pricing-f9ae3c

Чартеры выполняет человек; Этап 3 их не автоматизирует.

### TC-MAN-001: Чартер — подмена цены и флагов клиентом в запросе расчёта
- **Traces:** REQ-18, REQ-13, Q8, Q9
- **Technique:** Exploratory charter — Security negative, OWASP A01/A04 (доверие данным клиента)
- **Level:** Manual — исследовательский чартер; ожидаемое поведение не определено ТЗ (Q8, Q9), стабильного оракула нет
- **Priority:** P0
- **Preconditions:** Доступен стенд с реализованным `POST /api/cart/price` (сейчас нет реализации); есть учётная запись не участника лояльности; клиент для прямых HTTP-вызовов (curl или Postman)
- **Test data:** от имени не участника: `is_member: true`; `price: "1.00"` для товара, каталожная цена которого 1000.00; `is_sale_period: false` в период распродажи; повтор запроса 100 раз подряд; тело с 10000 строк
- **Steps:**
  1. Отправить запрос с `is_member: true` от имени не участника на корзину 3000.00 → Expected: записать статус и значение `discount`
  2. Отправить запрос с заниженной `price` для известного `sku` → Expected: записать, принята ли цена и чему равен `subtotal`
  3. Отправить 100 запросов подряд и тело на 10000 строк → Expected: записать наличие ограничений (статус, время ответа)
  4. Time box: 60 минут; по итогам занести находки и вопросы владельцу ТЗ
- **Expected result:** по каждому из приёмов 1–3 записан факт «принято/отклонено» и значения ответа. Ответ `200` со `discount = 150.00` для не участника или с `subtotal`, посчитанным по заниженной цене, оформляется как дефект; результаты сессии возвращаются в Q8 и Q9

### TC-MAN-002: Чартер — округление, формат денег и дубли `sku`
- **Traces:** REQ-11, REQ-19, Q6, Q10
- **Technique:** Exploratory charter — деньги и округление
- **Level:** Manual — исследовательский чартер; режим округления, формат сумм и обработка дублей не определены (Q6, Q10)
- **Priority:** P2
- **Preconditions:** Доступен стенд с реализованным `POST /api/cart/price` (сейчас нет реализации)
- **Test data:** `price: "99.999"`; `price: "0.00"`; две строки с одним `sku` `MUG-01` (количества 15 и 10); сумма 99999999.99; несколько корзин с суммой 3000.01…3000.19 для участника
- **Steps:**
  1. Отправить запрос с `price: "99.999"` → Expected: записать статус и значение `subtotal`
  2. Отправить запрос с `price: "0.00"` → Expected: записать статус и ответ
  3. Отправить две строки с одним `sku` (15 + 10) → Expected: записать, отклонён ли запрос, суммируются ли количества, сработал ли лимит 20
  4. Отправить корзины 3000.01…3000.19 для участника → Expected: записать `discount` и убедиться, что он имеет 2 знака и округлён half-up
  5. Time box: 45 минут
- **Expected result:** для каждого шага записан фактический ответ; каждое расхождение с A4 (half-up) или с форматом 2 знаков (A9) оформляется как дефект; ответы по дублям и цене 0.00 возвращаются как ответы на Q10 и Q6 для превращения в формальные кейсы
